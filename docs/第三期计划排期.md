# 第三期计划排期

> 本文档为**第三期计划排期**，汇总第二期交付后对检索层 / 知识图谱层 / ReAct 推理层 / 长期记忆 / 后置 Guardrail / 测试能力的逐层代码复核结论，并按优先级给出排期建议。承接 [第二期计划排期](第二期计划排期.md)。更新日期：2026-11-11（P1 召回阈值已落地，详见 [P1 进展](#p1检索质量与记忆可信化)）。

## 一、结论

第二期后系统已具备三大能力基础（ReAct 推理可见 / LLM Wiki / QA 长期记忆）与持久化地基，但在**可信性防线**上存在系统性缺口：召回无相似度阈值与冲突检测、图谱抽取无 schema 白名单与原文支撑校验、ReAct 允许跳过工具直接输出事实结论且 reasoning 不落审计、QA 记忆「点有帮助即 confirmed」且无管理员撤销、输出后置 Guardrail 与评估闭环整体空白。

> **2026-11-11 进展**：P1「召回阈值」已落地（`RAG_SCORE_FLOOR` / `RERANK_SCORE_FLOOR` 双层阈值 + 删除低分补位），smoke/judge 回归 Hallucination 0.6→1.0、AnswerRelevancy 0.73→0.93，详见第五节 P1。

第三期建议优先做 **P0：禁止项治理**（直接对应五条违规风险），其次补齐 **P1：检索质量与记忆可信化**，最后建设 **P2：审计与评估闭环**。

## 二、当前已具备的基础（承接第二期）

- 检索侧已有向量余弦 + 关键词加权融合分，可选 Rerank 精排，`RAG_TOP_K / RAG_RECALL_TOP_K` 独立生效；**2026-11-11 已补齐召回阈值过滤**（`RAG_SCORE_FLOOR` 向量相似度下限 + `RERANK_SCORE_FLOOR` 精排相关性下限，删除低分补位逻辑），smoke 回归 Hallucination 0.6→1.0、AnswerRelevancy 0.73→0.93，检索 Recall@5 0.28→0.83、误召回归零。
- 图谱侧已有 `entities / relations` 表、`lookup_entity` 只读工具、`extractionService` 抽取队列；实体/关系一律 `pending` 入库，需 admin/editor 人工 confirm，Agent 无任何写工具。
- 记忆侧已有 `qa_memory` 表（`pending / confirmed / rejected`）、`searchHistoricalQA`（仅召回 confirmed）、`applyFeedback`（helpful=true → confirmed，helpful=false → rejected）。
- Agent 侧已有工具调用白名单校验（编造工具名抛 `INVALID_TOOL`）、`SourceRegistry` 引用存在性与 `sourceIsValid` 校验、`MAX_SEARCH_CALLS` 检索预算与空结果熔断。
- 队列侧已有泛化 `createQueue` 工厂，承载索引 / 抽取 / QA 写回三类任务。

## 三、逐层检查结论

### A. 检索层（RAG / embedding / indexQueue）

| 检查项 | 结论 | 说明 |
| --- | --- | --- |
| 召回相关性打分 + reranker 阈值过滤 | ✅ 已实现（2026-11-11） | `semanticSearch` 双驱动按 `RAG_SCORE_FLOOR`（默认 0.3）过滤；rerank 结果按 `RERANK_SCORE_FLOOR` 过滤（校准值 0.5），精排未覆盖候选不再按融合分补位，全部淘汰时回退关键词兜底 |
| chunk 强制携带溯源元数据 | ⚠️ 部分 | 有 `documentId / title / category / version / offset / nextOffset`；缺 `sourceType / chunkId / namespace` |
| 召回片段冲突检测 | ❌ 缺失 | 全代码库无 `conflict` 标记与矛盾片段检测逻辑 |
| 分块/抽取前置过滤脏数据 | ⚠️ 部分 | 已有空白/纯标点碎片过滤与上传侧嗅探；缺 OCR 乱码率检测与最短 chunk 长度阈值 |
| createQueue 前置 hook 统一处理召回过滤/去重/冲突 | ❌ 缺失 | `createQueue` 是任务队列，检索链路无统一 hook |

### B. 知识图谱层

| 检查项 | 结论 | 说明 |
| --- | --- | --- |
| 抽取原文支撑校验 | ❌ 缺失 | LLM 返回 JSON 后直接 upsert，未校验 name/predicate 是否出现在原始 chunk，无 `unsupported` 标记，仅靠 prompt 软约束 |
| entityType / relationType schema 白名单 | ❌ 缺失 | prompt 中有枚举建议，代码层无任何校验，predicate 完全自由文本 |
| lookup_entity 只读 + 人工审核 | ✅ 基本满足 | 只读工具、pending 入库、人工 confirm；缺 `KG_AUTO_ACCEPT` 开关（默认即关闭，但无法做 A/B） |
| 关系入库冲突校验 | ⚠️ 部分 | 有三元组唯一约束与实体摘要 `needsReview`；同实体对不同 predicate 的冲突关系各写各的 pending 行，不进待审队列 |
| 关系绑定 chunk 溯源 | ⚠️ 部分 | `lookup_entity` 不返回 relations；sources 为 documentId 粒度，无 chunk 粒度绑定 |

### C. ReAct Agent 推理层

| 检查项 | 结论 | 说明 |
| --- | --- | --- |
| 事实类问题运行时校验（禁止跳过工具） | ❌ 缺失 | `SourceRegistry.validate` 只校验「出现过的 [Sx] 是否有效」，不要求至少一个引用；零工具零引用直接作答可通过 |
| 工具原始返回隔离 | ⚠️ 部分 | 工具返回走 ToolMessage、原文存 registry；无结构化「原始返回区 / 思考区」隔离与逐句比对 |
| 系统 prompt 强约束 | ⚠️ 部分 | 已有「资料不足如实说明、禁止编造」；缺「禁止大概/可能充当确定结论」与「冲突时不可单方面采信」措辞 |
| 工具调用白名单 | ✅ 已实现 | 未注册工具名直接抛 `INVALID_TOOL` |
| reasoning 完整留存可审计 | ❌ 缺失 | reasoning 仅存内存且持久化时被剥离，审计只记 `reasoningChars`，工具入参/返回不落审计 |
| reasoning 幻觉风险埋点 | ❌ 缺失 | 无编造实体、虚构来源、无视工具返回的检测 |

### D. QA 长期记忆（重点）

| 检查项 | 结论 | 说明 |
| --- | --- | --- |
| verified 标记字段 | ⚠️ 近似 | 用 `status pending/confirmed/rejected` 近似，无布尔 `verified` 与权重字段 |
| searchHistoricalQA 加权逻辑 | ⚠️ 部分 | 仅召回 confirmed（未核验根本不进上下文）；无 verified 权重排序，无「未人工核验」强制标注（因不召回未写） |
| consistent / memoryScore / risk 一致性校验 | ❌ 缺失 | 无与 RAG/KG 原始资料的校验、无评分、无 risk 标记 |
| invalid 标记 | ⚠️ 近似 | helpful=false → rejected 且检索过滤，等价实现；无独立 invalid 字段/原因 |
| 禁止仅凭「有帮助」认定正确 + 管理员撤销 | ❌ 缺失 | helpful=true 直接 confirmQa，无二次校验；无管理员撤销 confirmed 的接口 |
| 未核验记忆不单独支撑事实 | ✅ 基本满足 | 靠「不召回」实现；但 confirmed 记忆被当作已采信结论复用，缺「仍以原始 chunk 为准」的显式约束 |
| 记忆时间衰减 | ❌ 缺失 | 无任何衰减/权重计算 |
| 记忆污染测试能力 | ❌ 缺失 | 无错误记忆注入用例 |

## 四、禁止项扫描（违规风险）

| # | 禁止项 | 结论 |
| --- | --- | --- |
| 1 | 不允许未溯源的确定性事实输出 | ❌ 违规风险：零引用可通过 `validate` |
| 2 | 不允许 ReAct 跳过工具直接回答事实问题 | ❌ 违规风险：无运行时强制工具校验 |
| 3 | 不允许 verified=false 记忆作为唯一事实依据 | ✅ 规避：未核验记忆不召回 |
| 4 | 不允许 LLM 自由抽取无 schema 约束的实体关系 | ❌ 违规：无 type/predicate 白名单 |
| 5 | 不允许自动入库未经校验的图谱实体关系 | ✅ 规避：一律 pending + 人工 confirm |

## 五、建议排期

### P0：禁止项治理（可信性底线）

- [ ] 强制引用校验：`runAgent` 收尾处增加「事实类回答必须含 ≥1 个有效 `[Sx]`」校验，不满足则降级为「资料不足」话术或要求重答。
- [ ] 强制工具校验：middleware 记录本轮工具调用情况，未调用任何检索/图谱/记忆工具而输出确定性事实表述时拦截或重答。
- [ ] 抽取 schema 白名单：`entityType / relationType / predicate` 代码级枚举校验，白名单外直接丢弃。
- [ ] 抽取原文支撑校验：entity name/alias 与 predicate 必须在原始 chunk 文本中出现（含分词/别名匹配），不通过标记 `unsupported` 并拒绝入库或进待审。
- [ ] prompt 增补强约束：禁止「大概/可能」充当确定结论；资料冲突时只能如实说明冲突，不可单方面采信。
- [ ] 新增 `KG_AUTO_ACCEPT` 配置项（默认 false），为后续 A/B 对照铺路。

### P1：检索质量与记忆可信化

- [x] 召回阈值（**2026-11-11 已落地**）：`RAG_SCORE_FLOOR`（默认 0.3，0 关闭）/ `RERANK_SCORE_FLOOR`（默认 0.2，0 关闭）双层阈值过滤，低于阈值直接丢弃；`rerankTopN` 5→10 使精排具备淘汰空间；删除「精排未覆盖候选按融合分补位」逻辑（尾部候选即噪声）；阈值过滤后为空回退关键词兜底。阈值经 [retrieval-evaluate](../server/scripts/retrieval-evaluate.js) 校准：相关文档 rerank 分 ≥0.58、纯噪声 ≤0.23，`.env` 取 `RERANK_SCORE_FLOOR=0.5`。回归结果：Recall@5 0.28→0.83、MRR→0.89、falseHit→0；agent smoke 全绿（citationAccuracy=1）；LLM judge Hallucination 0.6→1.0、AnswerRelevancy 0.73→0.93（training 用例 0.2/0.45→1.0/0.86）。配套：单测覆盖 floor 过滤/全淘汰/关闭/null 降级；smoke 断言 onboarding 工具调用要求 2 次→1 次（检索干净后单次 search 即命中）。
- [ ] chunk metadata 补全：增加 `sourceType / chunkId / namespace` 三个字段，`SourceRegistry` 与 [Sx] 引用透传。
- [ ] 召回冲突检测：同一问题多片段结论矛盾时标记 `conflict`，prompt 中提示 LLM 不可单方面采信。
- [ ] 分块前置过滤增强：OCR 乱码率（替换字符/控制符占比）与最短 chunk 长度阈值。
- [ ] `qa_memory` 增加 `verified / memory_score / invalid_reason / last_verified_at` 字段；`helpful=true` 仅置 candidate，人工/后台才可置 verified。
- [ ] 管理员后台支持撤销错误的 confirmed 标记（新增改 status 路由）。
- [ ] 记忆检索加权：verified 优先；如引入未核验记忆辅助上下文，强制加「历史 AI 回答，未人工核验，不保证真实」前缀。
- [ ] 记忆时间衰减：长期未核验记忆随时间降权。
- [ ] `lookup_entity` 返回 relations 并绑定 chunk 粒度溯源 ID。

### P2：审计与评估闭环

- [ ] reasoning 正文（脱敏）+ 工具入参/返回完整落审计日志，支持按问题回放整条推理链。
- [ ] 复用 `createQueue` 新增 `eval` 队列：回答输出后异步做一致性校验（回答中的实体/事实能否在 chunk/KG/可信记忆中溯源），幻觉风险打标留存，不直接阻断。
- [ ] reasoning 幻觉埋点：编造实体、虚构来源、无视工具返回的规则/模型检测。
- [ ] 测试数据集补齐：冲突资料 case、图谱多跳推理 case、记忆投毒 case（支持注入错误记忆验证 Agent 是否被带偏）。
- [ ] 评估链路采集：embedding 召回 chunk 明细、lookup_entity 结果、记忆召回明细、ReAct 每步思考。
- [ ] 指标统计：域外拒绝率、引用溯源命中率、冲突处理正确率、ReAct 工具合规率、记忆污染率。
- [ ] A/B 对照矩阵：`MEMORY_ENABLED / AGENT_ENABLE_THINKING / KG_AUTO_ACCEPT / RAG_SCORE_FLOOR / RERANK_SCORE_FLOOR` 组合跑批脚本。

## 六、关键风险与前置依赖

- **强制引用/工具校验**会改变 Agent 出口行为，需先在评估集上回归，避免正常「寒暄/解释类」回答被误拦——建议先做问题分类（事实类 vs 闲聊类）再启用拦截。
- **原文支撑校验**依赖中文分词/别名匹配的质量，误杀率需通过评估集调参；schema 白名单需业务方先确认实体/关系枚举。
- **记忆字段改造**涉及 `qa_memory` 表结构变更与存量数据迁移，需配套迁移脚本并回写 status → verified 映射。
- **后置 Guardrail 与评估队列**依赖 LLM 调用预算，建议异步低优先级执行并限流。

---

## 七、最终建议

第三期按 **P0 → P1 → P2** 顺序推进。最值得优先投入的是 **P0 禁止项治理**——它直接消除「未溯源事实输出、跳过工具作答、无 schema 抽取」三条硬违规，是整个系统可信性的底线；其次是 **记忆可信化**（verified 字段 + 管理员撤销 + helpful 不直接确认），这是当前最容易被污染的入口。评估闭环（P2）虽然不直接阻断线上风险，但它是 P0/P1 改动效果的度量手段，建议与 P0 同步搭好最小可用版本（至少先落 reasoning 审计留存与五类 case 数据集）。
