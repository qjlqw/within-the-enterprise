# 第二期计划排期

> 本文档为**第二期计划排期**，汇总第一期交付后经代码复核确认的「未做」事项，并按优先级给出排期建议。承接 [当前项目的功能实现](当前项目的功能实现.md)。更新日期：2026-09-25。

## 一、结论

第一期已形成可运行的只读知识助手，但以下能力**尚未落地**：三大能力演进（ReAct 推理可见 / LLM Wiki / Agent 长期记忆）整体未实现；会话存储与向量索引仍未持久化；Backblaze B2 只完成 upload/delete；Upstash Vector / Redis 已配置并连接但缺 namespace 隔离；现有 HTTP 接口权限与生产配置未补齐；云端真实模型验收未执行。

第二期建议优先做**数据持久化与上线前置**，其次补齐**对象存储与外部驱动闭环**，再按真实业务需求引入三大能力与高级能力。

- 已具备 LangChain `createAgent` + ReAct + middleware，SSE 流式、工具调用限制、重试、引用校验。

## 三、未完成事项清单

- 向量索引仍为本地 JSON（`.runtime/vectors.json`），未做 namespace 隔离、未托管。
- 已有文档索引 / 历史数据的迁移脚本未做。

### C. Backblaze B2 补全

- 尚未实现 `list` / `download` 接口。
- 未用真实凭证跑通「上传 → 下载 → 删除」完整闭环。

### D. 外部驱动收尾

- 现有已发布文档未迁移到 Upstash。

### E. 上线前置项

- 现有 HTTP 接口的草稿可见性 / 回滚授权等权限未补齐。
- 生产 JWT 密钥未轮换、部署 CORS 来源未限定。
- 真实云端模型（通义千问）验收与人工语义评审未执行。

### F. 高级能力（按真实业务需求）

- HITL（发布审批 / 外部写入 / 人工确认）、MCP、Plan-and-Execute、Supervisor Multi-Agent、语义缓存、长期记忆。

## 四、建议排期

### P0：数据持久化与上线前置

- [ ] 会话存储持久化：迁移到 PostgresSaver 或 Supabase 会话表，明确与展示历史的职责，避免双份上下文。
- [ ] 向量索引持久化 + namespace 隔离：支持按知识库/租户隔离，索引携带文档 ID、版本与权限元数据。
- [ ] 现有 HTTP 接口权限补齐：统一草稿可见性、覆盖搜索 / 推荐 / 列表 / 详情 / 用户文档 / 收藏及读取入口，修复回滚等写入口授权。
- [ ] 生产 JWT 密钥轮换、CORS 来源限定。
- [ ] 真实云端模型（通义千问）验收 + 语义评审。

### P1：对象存储与外部驱动闭环

- [ ] Backblaze B2 `list` / `download` 接口补齐。
- [ ] Upstash Vector / Redis namespace 隔离（按知识库/租户区分索引与缓存 key）。
- [ ] 已有文档索引 / 数据迁移脚本。

### P2：三大能力演进（按需）

- [ ] 阶段 0 地基：namespace 隔离、embeddings 工厂、队列泛化工厂。
- [ ] ReAct 推理可见（后端 `reasoning` 事件 + 前端「思考中」面板）。
- [ ] LLM Wiki（entities/relations 表 + `lookup_entity` 工具 + 实体抽取）。
- [ ] Agent 长期记忆（默认关闭、支持用户清除）。

### P3：高级能力（按真实业务需求）

- [ ] 出现「发布审批 / 外部写入 / 人工确认」场景时，引入 HITL（`interrupt` / checkpointer）。
- [ ] 有外部工具生态需求时接 MCP。
- [ ] 有长任务需求时做 Plan-and-Execute。
- [ ] 只有出现明确角色分工与复杂流程时才做 Supervisor Multi-Agent。
- [ ] 语义缓存与长期记忆最后做。

## 五、关键风险与前置依赖

- **会话 / 向量持久化**依赖生产存储选型（Supabase Postgres / Upstash），需先确定部署环境。
- **Backblaze B2 list/download 与真实闭环验证**依赖真实 bucket / token 凭证。
- **三大能力与高级能力**依赖真实业务场景（如是否需要审批、多租户、外部工具），不应在无需求时提前建设。
- **现有权限补齐**需逐一核查既有路由并做回归，非前端 `AuthGuard` 可替代。

---

## 六、最终建议

第二期按 **P0 → P1 → P2 → P3** 顺序推进，优先把「能上线、能持久、能审计」做好，再按真实业务需求引入三大能力演进与高级能力。最值得优先投入的是 **数据持久化与权限补齐**；最应推迟的是 **MCP、多 Agent、长期记忆** 以及没有实际审批场景支撑的 **HITL**。
